# Лабораторная работа №2 — Связи между классами (вариант 15, Плейлист)

Язык: C#. Работа продолжает ЛР1: тот же домен (треки и плейлист), в репозиторий добавлены связи, иерархия, интерфейсы и полиморфизм.

## Цель

Научиться собирать программу из нескольких классов: выбирать вид связи между ними, строить иерархию только там, где она оправдана, выносить изменяемое поведение в интерфейсы и заменять ветвление по типу полиморфизмом. Контрольный результат — новая разновидность сущности добавляется одним новым классом, без правки существующего кода.

## Задание 1. Связи в домене

Создан класс Duration, в который перенесена логика проверки и хранения длительности. Класс связан с Track композицией: объект Duration создаётся внутри конструкторов Track и не отдаётся наружу; без трека длительность не существует. PlayList связан с элементами агрегацией: метод Add принимает объект извне и сохраняет ссылку; удаление элемента из плейлиста или самого плейлиста не уничтожает объекты треков (и других MediaItem). Критерий выбора связи — время жизни: часть при композиции не живёт отдельно от целого, при агрегации объект существует независимо.

## Задание 2. Иерархия

Добавлен абстрактный класс MediaItem с общим состоянием (ключ, название, исполнитель, число прослушиваний) и общим алгоритмом Play. Метод Play не помечен как virtual/abstract, поэтому наследники не могут его переопределить (в C# sealed на «первом» объявлении метода писать нельзя — sealed допускается только при override). Обязанность наследников — абстрактный метод GetDuration(). Также добавлен виртуальный GetGenres() с пустым результатом по умолчанию. Наследники: Track (длительность через Duration, жанры), Podcast (эпизоды), Audiobook (закладка позиции прослушивания). Конструкторы наследников вызывают base(). Глубина иерархии — один уровень наследников.

## Задание 3. Интерфейс и полиморфизм

Объявлен интерфейс SelectionRule с методом sort. Написаны три реализации: KeySelectionRule (по ключу/порядку), PopularSelectionRule (по числу прослушиваний), RandomSelectionRule (случайный порядок). Правило передаётся в PlayList извне через конструктор и метод SetRule, внутри плейлиста не создаётся. PlayList хранит MediaItem[] и вызывает rule.sort(items, count), не зная конкретной реализации. Интерфейс — абстракция (известен только контракт); разное поведение при одном и том же вызове — полиморфизм. Коллекция разнородных элементов обрабатывается без проверок типа (instanceof/is/switch по типу).

## Задание 4. Композиция вместо наследования

Дана была бы иерархия MediaItem → Track → PremiumTrack → PremiumExplicitTrack. Вместо неё использована композиция: Track имеет уровень доступа и возрастную маркировку как отдельные объекты. В файле Level_Age.cs объявлены интерфейсы AccessLevel (FreeAccess, PremiumAccess) и AgeRating (NiceRating, BadRating) и их реализации. В Track добавлены поля access и rating, они задаются в конструкторе (с значениями по умолчанию Free и Nice). Метод CanPlay(bool userIsPremium) делегирует проверку объекту AccessLevel: для Free всегда можно слушать, для Premium — только если userIsPremium == true. Параметр true/false передаёт вызывающий код и имитирует наличие или отсутствие подписки у пользователя. Отношение «является» — наследование (PremiumTrack является Track); отношение «имеет» — композиция (Track имеет AccessLevel и AgeRating). Признаки вынесены в отдельные типы, комбинаторный рост подклассов не нужен.

## Задание 5. Расширение — радиопоток

Добавлен класс RadioStream : MediaItem — радиопоток без фиксированной длительности (GetDuration возвращает 0). Новый тип подключается одним новым файлом и одной строкой создания/добавления в Program. Существующие классы не изменялись: плейлист уже работает с MediaItem и вызывает GetDuration полиморфно. Дешёвым изменение сделали полиморфизм и программирование к базовому типу.

## Итоговая структура

MediaItem (abstract) ← Track (композиция Duration, AccessLevel, AgeRating), Podcast, Audiobook, RadioStream. PlayList агрегирует MediaItem[] и использует SelectionRule. SelectionRule реализуют KeySelectionRule, PopularSelectionRule, RandomSelectionRule.
Для наследников формулируется отношение «является». Клиентский код работает через интерфейс или базовый тип. Новая разновидность (радиопоток) добавляется одним классов.
