## Предметная область

Проект моделирует музыкальный плейлист. 
- **Основная сущность:** `Track` (Трек)
- **Производные типы:** `Podcast` (Подкаст) и `Audiobook` (Аудиокнига)

### Основные инварианты (правила) для `Track`:
1. Длительность трека должна находиться в диапазоне **от 1 до 3600 секунд** включительно.
2. Название трека не должно быть `null` или пустой строкой `""`.
3. Ключ (номер) трека не может быть отрицательным.
4. Число прослушиваний должно увеличиваться при воспроизведении и **не должно уменьшаться**.
5. `Track`, `Podcast` и `Audiobook` должны корректно учитывать воспроизведение, при этом производные типы могут иметь собственную реализацию `GetDuration()`.

## Задание 1. Модульные тесты на инварианты

Тесты организованы по классической схеме **AAA (Arrange — Act — Assert)**:
1. **Arrange** — подготовка объекта и входных данных.
2. **Act** — выполнение проверяемого действия.
3. **Assert** — проверка результата или ожидаемого исключения.

### Проверяемые правила и использование xUnit:

| Правило | Допустимые данные | Недопустимые данные / Ожидаемое поведение | Атрибуты и методы xUnit |
| :--- | :--- | :--- | :--- |
| **Длительность** | От 1 до 3600 | Меньше 1 или больше 3600 | `[Fact]`, `Assert.Throws<ArgumentException>` |
| **Название** | Непустая строка (`Song`) | `null` или `""` | `[Fact]`, `Assert.Throws<ArgumentException>` |
| **Ключ** | Неотрицательное значение | Отрицательное значение | `[Fact]`, `Assert.Throws<ArgumentException>` |
| **Прослушивания** | `Play()` увеличивает счётчик | Счётчик не должен уменьшаться | `[Fact]`, `Assert.Equal` |
| **Полиморфизм** | Воспроизведение увеличивает счётчик у всех типов | Нарушение поведения производного класса | `[Theory]`, `[InlineData]`, `Assert.Equal` |

*Для проверки исключений используется `Assert.Throws`, для проверки обычных значений — `Assert.Equal`.*

## Задание 3. Тестовые дублёры и изоляция зависимостей

Для того чтобы тесты были предсказуемыми и не зависели от реального времени, случайных чисел или БД, используется **внедрение зависимостей (Dependency Injection, DI)**. Зависимости передаются в классы снаружи через конструктор.

### Используемые компоненты:

- **`ITimeSource`** — интерфейс источника времени.
- **`FixedTimeSource`** — заглушка (Stub), возвращающая заданное время.
- **`IRandomSource`** — интерфейс источника случайных чисел.
- **`FixedRandomSource`** — тестовая реализация, возвращающая заранее заданные числа.
- **`RandomSelectionRule`** — правило, использующее случайность для перемешивания.
- **`InMemoryTrackRepository`** — хранилище треков в памяти (Fake).
- **`PlaylistService`** — сервис, который воспроизводит трек, фиксирует время и сохраняет его.

### Как тестируются компоненты:
- **Время:** Тесту передаётся фиксированная дата через `FixedTimeSource`. После вызова `PlaylistService.Listen()` тест проверяет точное значение `LastListenedAt` у трека, независимо от реальной даты запуска теста.
- **Случайность:** `FixedRandomSource` возвращает заданные значения (числа используются как индексы массива). Это позволяет воспроизвести один и тот же порядок перемешивания при каждом запуске и проверить, что все элементы остались в коллекции.
- **Хранилище:** `InMemoryTrackRepository` позволяет после прослушивания проверить сохранённые данные и их количество без использования реальной БД.

### Виды тестовых дублёров:
| Вид | Назначение | Пример в проекте |
| :--- | :--- | :--- |
| **Stub** (Заглушка) | Возвращает заранее заданное значение | `FixedTimeSource` |
| **Fake** (Фейк) | Упрощённая, но работающая реализация | `InMemoryTrackRepository` |
| **Mock** (Мок) | Проверяет вызовы и аргументы | Используется для проверки вызовов сохранения |
| **Spy** (Шпион) | Реальный объект, записывающий вызовы | Объект с журналом обращений |

## Задание 5. Мутационный анализ

Мутационный анализ позволяет оценить качество тестов. В код намеренно вносится ошибка (мутация). Если тесты падают — ошибка обнаружена. Если все тесты проходят — тестов недостаточно.

### Таблица мутаций для варианта 15:

| Мутация (вносимая ошибка) | Какой тест должен обнаружить ошибку |
| :--- | :--- |
| Разрешить уменьшение числа прослушиваний | Тест, проверяющий, что счётчик не уменьшается |
| Заменить `duration > 3600` на `duration > 3601` | Тест на отклонение длительности 3601 секунда |
| Удалить проверку пустого названия | Тесты для `null` и пустой строки |
| Пропустить первый трек при вычислении суммарной длительности | Тест суммарной длительности нескольких треков |
| Возвращать первый трек вместо самого популярного | Тест поиска популярного трека, где первый — не самый популярный |

*Мутация считается обнаруженной, если хотя бы один подходящий тест падает (завершается с ошибкой).*
